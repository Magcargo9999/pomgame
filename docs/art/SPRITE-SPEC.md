# 스프라이트 규격 v1 (빚더미 목장)

모든 도트 작업의 기준이다. 어긋나면 불합격이다. 상위 문서: `docs/design/GDD-v0.1.md` §4, 결정 기록 10·13.

## 1. 캔버스와 앵커
| 종류 | 셀 크기 | 몸이 차지할 영역 | 앵커(발이 닿는 점) |
|---|---|---|---|
| 돼지 성체 | 32×32 | 가로 24~28, 세로 18~22 | (16, 29) |
| 돼지 자돈 | 32×32 | 가로 14~18, 세로 11~14 | (16, 29) |
| 사람(플레이어·NPC) | 16×32 | 머리부터 발까지 28~30 | (8, 31) |
| 타일 | 16×16 | 꽉 채움, 이음매 없이 반복 | 없음 |
| 아이콘 | 16×16 | 가운데 14×14 | 없음 |

- 발이 닿는 줄(앵커 y)은 모든 프레임에서 같다. 점프 프레임만 예외다.
- 위에서 비스듬히 본 시점(¾ top-down)이고, 빛은 왼쪽 위에서 온다.

## 2. 품질 규칙 (자동 검사 + 눈 검사)
**자동 검사 (스크립트로 확인, 하나라도 실패하면 불합격)**
1. PNG 크기가 셀 × 프레임 수와 정확히 같다.
2. 알파 값은 0 또는 255뿐이다(반투명 금지).
3. 모든 색이 `docs/art/palette.json`에 있다.
4. 한 스프라이트에 쓴 불투명 색은 12개 이하다.
5. 고립 픽셀(상하좌우 이웃 중 같은 색이 하나도 없는 1px)은 외곽선과 눈을 빼고 0개다.
6. 외곽선에 순검정 `#000000`을 쓰지 않는다. 그 재질 램프의 가장 어두운 색을 쓴다.
7. 프레임마다 앵커 행에 불투명 픽셀이 있다(발이 땅에 닿음).

**눈 검사 (1배 크기에서 판단, 보고서에 체크)**
- 1배 크기에서 실루엣만 보고 축종과 방향을 알 수 있다.
- 눈은 1~2px로 보인다. 다리는 1px 이상 틈으로 서로 떨어져 있다.
- 머리는 몸 크기의 30% 이상이다(귀여운 비율, 작은 해상도 가독성).
- 재질마다 램프(같은 색의 명암 단계) 3~4단계를 쓴다. 의도한 디더링(점 섞기 무늬)만 허용한다.
- 같은 개체의 프레임 사이에서 색, 비율, 외곽선 두께가 바뀌지 않는다.

## 3. 유전 변이용 색 슬롯 (그리지 않고 색만 바꿈)
돼지 몸의 털·피부는 아래 **마커 색**으로 칠한다. 게임이 실행될 때 유전형 팔레트로 바꾼다.
| 슬롯 | 마커 색(밝음→어두움) | 용도 |
|---|---|---|
| coat | `#ff00ff #cc00cc #990099 #660066` | 기본 털색 |
| spot | `#00ffff #00cccc #009999 #006666` | 반점·띠 무늬 |
| snout | `#ffff00 #cccc00 #999900` | 코·귀 안쪽·발굽 |
무늬(점박이, 흰 띠, 버크셔 흰 반점 6곳)는 몸 위에 겹치는 **별도 무늬 레이어** PNG(같은 크기, spot 슬롯 색만 사용)로 만든다.
미리보기용 실제 색 팔레트는 `docs/art/breeds.json`에 품종별로 둔다.

## 4. 애니메이션
| 이름 | 프레임 | 프레임당 ms | 반복 | 동작 규칙 |
|---|---|---|---|---|
| idle | 2 | 500 | 반복 | 몸통 1px 위아래(숨쉬기). 다리는 고정 |
| walk | 4 | 140 | 반복 | 앞다리와 뒷다리를 대각선으로 교차. 2번째와 4번째 프레임에 몸통 1px 위로 |
| eat | 2 | 300 | 반복 | 머리를 2~3px 내려 땅에 코. 꼬리 1px 흔들기 |
| sleep | 2 | 800 | 반복 | 엎드린 자세. 몸통 1px 부풀기. "z"는 그리지 않음(UI가 그림) |
| happy | 3 | 120 | 1회 | 앵커에서 2px 점프 후 착지 |

**방향**: down(정면), up(뒷모습), right(옆모습). left는 right를 좌우 반전해서 쓰고 따로 그리지 않는다.

**시트 배치**: 행 = 애니메이션×방향, 순서는 idle, walk, eat, sleep, happy × down, up, right(총 15행). 열 = 프레임. 빈 칸은 투명.
돼지 성체 시트 크기 = 32×4(최대 프레임, walk) 가로, 32×15 세로 = **128×480**.

**메타데이터** `<이름>.json`:
```json
{"cell":[32,32],"anchor":[16,29],"slots":["coat","spot","snout"],
 "anims":{"idle_down":{"row":0,"frames":2,"ms":500,"loop":true}}}
```

## 5. 일관성을 지키는 제작 방법 (필수)
1. **기준 포즈만 생성한다.** 방향별 idle 1프레임(정면·뒷모습·옆모습)만 이미지 생성으로 만든다.
2. **생성 지시**: 정사각형 512×512, 32×32 격자이며 한 픽셀이 16×16 블록, 몸 전체가 가운데, 단색 면, 안티에일리어싱 금지, 그라디언트 금지, 그림자 금지, 배경은 단색 `#00ff00`. 이렇게 하면 블록 크기(16)를 알고 있으므로 정확히 줄일 수 있다.
3. **나머지 프레임은 생성하지 않는다.** 기준 포즈를 픽셀 단위로 편집해서 만든다(다리 픽셀 교체, 몸통 1px 이동, 머리 내리기). 이미지 생성으로 프레임을 따로 만들면 프레임마다 생김새가 달라진다.
4. 줄이기는 셀마다 최빈색(가장 많이 나온 색)을 쓴다. 평균을 내면 경계가 흐려진다. 그다음 팔레트에서 가장 가까운 색으로 맞추고, 외곽선을 정리하고, 고립 픽셀을 지운다.
5. 생성이 규격에 안 맞으면 지시를 고쳐 다시 생성한다. 손으로 고칠 수 있는 범위는 픽셀 20개 정도까지다.

## 6. 산출물 (자산 하나마다)
```
assets/sprites/<축종>/<이름>.png          시트(마커 색)
assets/sprites/<축종>/<이름>.<무늬>.png   무늬 레이어
assets/sprites/<축종>/<이름>.json         메타데이터
art-review/<이름>_x8.png                  8배 미리보기(품종 색 적용)
art-review/<이름>.html                    애니메이션 미리보기(캔버스, image-rendering: pixelated, 1·4·8배)
art-review/<이름>.report.md               자동 검사 결과 + 눈 검사 체크 + 남은 문제
```

## 7. 도구
- 스크립트는 **Node**(설치됨)나 PowerShell/.NET으로 작성한다. Codex 에이전트 안에서는 Python이 권한 오류로 실행되지 않는다(2026-11-18 시험).
- 새 패키지를 설치하기 전에는 god에게 묻는다.
- 검사 스크립트: `tools/sprite-validate.*`(자동 검사 7항목). 커밋 전에 반드시 돌린다.
