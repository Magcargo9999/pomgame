## 0. 공통 규칙

### 0.1 시간
| 단위 | 값 |
|---|---|
| 1 게임일 | 실시간 12분 (낮 9분 + 밤 3분) |
| 1 계절 | 28일 |
| 1 년 | 4계절 = 112일 |
| 빚 상환일 | 매 계절 마지막 날 |

축종마다 생물학적 시간을 다르게 압축한다(돼지 1일 ≈ 실제 4.5일, 소 1일 ≈ 실제 7일, 닭 1일 ≈ 실제 3일). 단계 길이는 각 축종 표에 게임일로 직접 적는다.

### 0.2 모든 가축의 공통 상태 변수 (0~100 정규화, 물리량은 실제 단위)
```json
{
  "id": "PIG-000123",
  "species": "pig",
  "sex": "F",
  "ageDays": 18,
  "stage": "grower",
  "weightKg": 61.2,
  "bcs": 3.0,
  "health": 92,
  "stress": 18,
  "hygiene": 75,
  "hunger": 20,
  "affinity": 40,
  "genome": { "loci": {}, "bv": {} },
  "pedigree": { "sire": "PIG-000088", "dam": "PIG-000091", "F": 0.0625 },
  "traits": {},
  "flags": ["castrated"]
}
```
- `bv` = 육종가(Breeding Value, 유전적으로 자식에게 물려주는 능력, 정규분포 점수)
- `F` = 근교계수(Inbreeding coefficient, 0~1)
- `bcs` = 체형점수(Body Condition Score, 1~5)

### 0.3 일일 갱신 순서 (모든 축종 공통 tick)
```
1. 사료 섭취 → 에너지/단백질/섬유 흡수
2. 성장(체중, 부위별 조직 축적)
3. 환경 판정(청결, 밀도, 온도, 운동) → stress 갱신
4. 질병 판정(상태 머신, §0.5)
5. 생산(우유, 달걀)
6. 단계 전이 판정(상태 머신, §0.4)
```

### 0.4 생애 상태 머신 (공통 골격)
```
[Newborn] --이유일--> [Juvenile] --육성종료--> [Grower]
[Grower] --성성숙 & 미거세--> [Breeder]   (교배 가능)
[Grower] --비육 지정--> [Finisher] --출하 창 진입--> [MarketReady] --판매--> [Sold]
[Breeder] --임신--> [Pregnant] --분만--> [Lactating] --건유/이유--> [Breeder]
[어느 상태든] --health=0--> [Dead]
[Breeder] --노령/번식장애--> [Cull] --> 도축 판매(저등급)
```
JS 구현: `transitions = { stage: [{to, when:(a)=>bool}] }`. 매일 첫 번째로 참이 되는 전이만 실행한다.

### 0.5 질병 상태 머신
```
Healthy --감염확률 p--> Subclinical(무증상, 생산성 -10%, 체세포수 상승)
Subclinical --3일 내 미발견--> Clinical(생산성 -50%, 판매 불가)
Subclinical --검사 발견 + 처치--> Recovering
Clinical --치료--> Recovering --5일--> Healthy
Clinical --7일 방치--> Chronic(영구 -20%) 또는 Dead(p=0.15)
치료 중 항생제 사용 → withdrawalDays 동안 우유·고기 판매 금지 (현실의 휴약기간)
```
```js
p_infect = base[disease] * (1 - hygiene/100) * (1 + stress/100) * densityFactor * (1 - vaccine)
```

## 1. 등급제 고증과 게임 시스템

### 1.1 돼지 (육질 중심)

#### 현실 기준 (2018 개정 돼지도체 등급, 탕박 기준) [검증]
등급은 **1+, 1, 2, 등외** 네 단계다. 한국 돼지에는 1++가 없다. 1++는 소고기 등급이다.

**1차 등급** (규격: 도체중과 등지방두께)
| 등급 | 도체중(kg) | 등지방두께(mm) |
|---|---|---|
| 1+ | 83 이상 93 미만 | 17 이상 25 미만 |
| 1 | 80 이상 98 미만 | 15 이상 28 미만 |
| 2 | 그 외 | 그 외 |

**2차 등급** (육질): 삼겹살 상태(두께와 지방 정도), 지방침착도(근내지방), 육색(No.1~7, 중간이 좋음), 지방색(No.1~7, 흰색일수록 좋음), 육조직감.

**최종 등급**: 1차와 2차 중 낮은 쪽이다. 결함(PSE 물퇘지, DFD, 근출혈, 농양, 방혈불량 등)이 있으면 강등되거나 등외가 된다.

#### 게임 등급 체계
현실의 1+ 위에 게임 전용 최상위 등급 **"1+ 명품(★)"**을 둔다. UI에 "게임 전용"으로 표기해서 고증 논란을 피한다.

#### 사육 변수와 생애 단계
| 단계 | 게임일 | 체중(kg) | 핵심 관리 |
|---|---|---|---|
| 포유자돈 | 0~4 | 1.4→7 | 보온(32℃), 철분 주사(빈혈 방지), 초유 |
| 이유자돈 | 5~12 | 7→30 | 이유 스트레스, 고단백 사료, 설사병 |
| 육성돈 | 13~24 | 30→70 | 골격과 근육. 라이신을 충분히 |
| 비육돈 | 25~40 | 70→115 | 지방 축적. 출하 창은 36~42일 |

#### 사료 배합 (사료 배합기 해금 후 직접 조절, 그 전에는 시판 사료 3종)
| 원료 | 효과 |
|---|---|
| 옥수수 | 에너지 ↑, 지방색 약간 황색화 |
| 보리 | 에너지 중간, **지방을 희고 단단하게** (현실의 보리 비육) |
| 대두박 | 단백질/라이신 ↑ → 살코기 ↑, 근내지방 ↓ |
| 잔반·불포화유 | 싸다. **지방이 무르고 노래짐**(지방색 감점) |
| 비타민E 첨가제 | 육색 안정, 산화 방지 |

#### 일일 성장 수식
```js
// 평균일당증체량 (ADG: Average Daily Gain, kg/일)
ADG = stageBase[stage]                        // 이유 0.45, 육성 0.75, 비육 0.9
    * (1 + bv.growth * 0.08)
    * feedEnergyFactor                        // 0.7~1.15
    * (health/100)
    * (1 - stress/200)
    * thermalFactor;                          // 적정온도 밖이면 감소

fatRatio = 0.18 + 0.10*(energy/protein - 1)   // 에너지 과잉이면 지방 쪽으로
         - 0.04*exerciseLevel                 // 운동장 면적, 0~1
         - bv.lean * 0.03;
backfatMm += ADG * fatRatio * 9.5;            // 등지방 누적 계수, 출하 시 15~28mm가 나오도록 튜닝

// 근내지방(IMF %)은 비육기에만 의미 있게 쌓인다
if (stage === 'finisher')
  imf += 0.03 * (1 + bv.imf*0.15) * lysineRestrictFactor * breedIMF * (1 - stress/150);
// lysineRestrictFactor: 비육 후기 라이신 약간 제한 → 1.25. 과하면 성장 저하
// breedIMF: 듀록 1.3, 버크셔 1.25, 요크셔 0.9, 랜드레이스 0.9, 재래흑돼지 1.35

fatColorScore = clamp(1 + 4*unsatFatShare - 1.5*barleyShare, 1, 7);  // 낮을수록 좋음
```

#### 도축 전 스트레스와 PSE (물퇘지: 창백하고 흐물거리며 물이 빠지는 고기)
현실의 원인은 두 가지다. 할로탄 유전자(RYR1, 스트레스 감수성), 그리고 도축 직전의 급성 스트레스(혼합, 장거리 수송, 거친 취급)다. 반대로 만성 스트레스나 장기 절식으로 근육 속 글리코겐이 고갈되면 DFD(어둡고 단단하고 건조한 고기)가 생긴다.
```js
preStress = transportLevel*25 + mixedUnfamiliar*20 + roughHandling*30
          + (fastHours < 12 ? 10 : 0) + stress*0.3;
pPSE = halothaneBase[genotype] * (1 + preStress/50);  // NN 0.02, Nn 0.08, nn 0.35
pDFD = (fastHours > 24 ? 0.10 : 0.01) + chronicStress/400;
```
출하 전날 하는 행동 선택이 게임플레이가 된다. 계류장(휴식)을 쓰고, 같은 우리끼리 출하하고, 12~18시간 절식하는 것이 최선이다.

#### 최종 등급 함수
```js
function gradePig(c){   // c: 도체 판정값
  const g1 = (c.carcassKg>=83&&c.carcassKg<93&&c.backfat>=17&&c.backfat<25) ? 3
           : (c.carcassKg>=80&&c.carcassKg<98&&c.backfat>=15&&c.backfat<28) ? 2 : 1;
  let q = 0;
  q += c.imf>=3.0?3 : c.imf>=2.0?2 : 1;                 // 지방침착도
  q += (c.color>=3&&c.color<=5)?3 : (c.color===2||c.color===6)?2 : 1;  // 육색
  q += c.fatColor<=2?3 : c.fatColor<=4?2 : 1;           // 지방색
  q += c.bellyScore>=0.7?3 : c.bellyScore>=0.4?2 : 1;   // 삼겹살 상태
  const g2 = q>=11?3 : q>=8?2 : 1;
  let g = Math.min(g1,g2);                              // 3=1+, 2=1, 1=2
  if (c.PSE||c.DFD) g = Math.max(0, g-2);               // 0=등외
  if (g===3 && c.imf>=4.0 && c.fatColor<=1 && !c.PSE) return '1+★';
  return ['등외','2','1','1+'][g];
}
```
| 등급 | 지육 가격 배수 |
|---|---|
| 1+★ | ×1.45 |
| 1+ | ×1.15 |
| 1 | ×1.00 |
| 2 | ×0.85 |
| 등외 | ×0.60 |

### 1.2 젖소 (우유 품질과 육질)

#### 현실 원유 등급 (한국 기준) [검증]
| 체세포수 등급 | 개/ml |
|---|---|
| 1 | 20만 미만 |
| 2 | 20만~35만 |
| 3 | 35만~50만 |
| 4 | 50만~75만 |
| 5 | 75만 이상 |

| 세균수 등급 | 개/ml |
|---|---|
| 1A | 3만 미만 |
| 1B | 3만~10만 |
| 2 | 10만~25만 |
| 3 | 25만~50만 |
| 4 | 50만 이상 |

유지방률과 유단백률은 기준치(대략 유지방 3.4%, 유단백 3.0~3.2%)보다 높으면 가산, 낮으면 감산한다.
- **체세포수**: 유방 건강을 보여 준다. 유방염이 있으면 급등한다.
- **세균수**: 착유 위생, 착유 기구 세척, 냉각(착유 후 빠르게 4℃로)을 보여 준다.

#### 비유 곡선 (Wood 모델, 현실 연구에서 쓰는 식)
```js
dailyMilkKg = a * Math.pow(t, b) * Math.exp(-c * t);  // t = 분만 후 게임일
// 게임 기본값: a=22, b=0.20, c=0.045 → 약 5일차 정점, 56일(실제 305일 상당)에 건유
```

## 2. 유전과 품종개량

### 2.1 두 층 구조
1. **질적 형질(멘델 유전)**: 털색, 무늬, 뿔, 특수 유전자. 대립유전자 2개로 표현형이 결정된다. 스프라이트를 바꾼다.
2. **양적 형질(다유전자)**: 성장, 마블링, 유량 등. 육종가(BV)라는 연속값을 쓴다. 능력치를 바꾼다.

### 2.2 유전자좌 정의 테이블 (`data/loci.json`)
현실 유전자명을 따랐다. 대립유전자 순서는 우성이 앞이다.

### 2.3 교배 알고리즘
```js
function breed(sire, dam, rng){
  const child = { loci:{}, bv:{} };
  // 1) 멘델 유전: 부모에게서 대립유전자를 하나씩
  for (const L of lociFor(sire.species)){
    if (L.mode==='sexlinked_Z'){ /* 수컷 ZZ, 암컷 ZW: 딸은 아버지의 Z만 받는다 */ }
    let a = pick(sire.loci[L.locus], rng), b = pick(dam.loci[L.locus], rng);
    if (rng() < mutationRate(L)) a = mutate(L, a, rng);    // §2.5
    child.loci[L.locus] = [a,b];
  }
  // 2) 양적 형질: 부모 평균 + 멘델 샘플링 (실제 동물육종학의 무한소 모형)
  const Fbar = (sire.F + dam.F)/2;
  for (const t of traitsFor(sire.species)){
    const sd = Math.sqrt(0.5*(1-Fbar)) * sigmaA[t];
    child.bv[t] = (sire.bv[t]+dam.bv[t])/2 + gauss(rng)*sd;
  }
  child.F = coancestry(sire, dam);   // 자식의 근교계수 = 부모의 혈연계수
  return child;
}
```

### 2.4 혈통과 근친 페널티
- 혈통 저장: `pedigree` 맵 `{id: {sire, dam, F}}`. 근교계수는 표 방법(tabular method)으로 계산하고, 성능을 위해 8세대까지만 본다.
```js
// 근교 퇴화 (현실: F 1%당 유량 약 0.3%, 번식력과 생존율 하락)
traitPenalty = 1 - F * inbreedingDepression[trait];  // growth 0.25, milk 0.30, fertility 0.6, survival 0.4
```
- 근친교배는 치사·질병 열성 유전자를 동형접합으로 만드는 현실적 위험이 있다. 반대로 원하는 열성 형질(MSTN, 실키)을 고정하는 지름길이기도 하다. 이것이 핵심 딜레마다.
- 교배 화면에는 예상 F와 위험 등급을 표시한다.

| F | 등급 |
|---|---|
| < 3.125% | 안전 |
| < 6.25% | 주의 |
| < 12.5% | 위험 |
| 그 이상 | 근친 |

### 2.5 돌연변이
```js
mutationRate(L) = 0.002 * (geneLabLevel>=2 ? 2 : 1) * eventBoost;   // 좌위당, 세대당
```
- 변이 결과는 해당 좌위의 희귀 대립유전자다(예: 칡소 브린들, 백색 반점, 흰자 고밀도).
- 게임을 위해 현실보다 훨씬 높게 잡은 확률이다. 설정에서 "현실 모드"로 1/100 배를 고를 수 있다.

### 2.6 희귀 개체와 능력치 상한 돌파
```js
cap[trait] = baseCap[species][trait]
           + Σ capGenes(loci)                   // 예: MSTN mhmh → 육량 상한 +15%
           + generationBonus;                   // 계보 내 등록 세대 수 × 1%, 최대 10%
rarityScore = Σ rarityWeight[expressed allele]  // 표현된 희귀 형질
            + bvPercentile*3                    // 상위 퍼센타일
            + (F < 0.03 ? 1 : 0);
```
| 등급 | 점수 | 연출 |
|---|---|---|
| 일반 | 0~2 | 기본 팔레트 |
| 우량 | 3~4 | 테두리 반짝임 |
| 희귀 | 5~6 | 고유 무늬 레이어 |
| 영웅 | 7~8 | 고유 팔레트 + 실루엣 변형(뿔, 체형) |
| 전설 | 9+ | 이름 부여, 경매장 특별 회차, 혈통서 금박 |

**희귀 개체 예시 경로**
- 버크셔(흑색 + 여섯 군데 흰 반점) × 듀록(적색)
  → F2에서 적색 + 반점 개체가 나온다(e/e + 점박이 조합).
  → 근내지방 BV 상위 5%와 겹치면 "적반점 명품돈"(희귀)이 된다.
- 한우 × 유전자 분석 → 숨은 MSTN 보인자 2마리를 찾아 교배한다.
  → 1/4 확률로 이중근육 개체가 나온다. 육량 상한은 돌파하지만 마블링이 낮고 난산 위험이 있다.
  → 이 개체를 다시 고마블링 라인과 교배해서 두 장점을 모은다.

- **3년차**: 유전자 분석실과 한우로 큰 수익과 장기 투자를 시작한다.
- **4년차**: 경매와 숙성으로 희귀 혈통의 가치를 현금화한다.

밸런스 검증은 몬테카를로 시뮬레이터(규칙을 그대로 돌려 1,000회 플레이)로 한다. 평균적인 플레이어가 3.5~4.5년에 청산하도록 튜닝한다.

## 4. 픽셀 그래픽 제작 에이전트

### 4.1 결론
가능하지만 **이미지 생성만으로는 일관성이 나오지 않는다.** 이미지 생성 모델은 격자에 정확히 맞는 픽셀, 고정 팔레트, 정확한 해상도를 보장하지 못한다. 일관성은 다음 세 가지에서 나온다.
1. 고정 팔레트와 규격 문서
2. 파이썬 후처리(격자 맞추기, 팔레트 강제, 검증)
3. **변이는 그리지 않고 팔레트 교체로 만든다**(§2.7)

### 4.2 규격
| 리소스 | 캔버스 | 비고 |
|---|---|---|
| 아이템·UI 아이콘 | 16×16 | 1px 외곽선 |
| 플레이어·NPC | 16×32 | 4방향 × 걷기 4프레임 |
| 가축 성체 | 32×32 | 걷기 4, 먹기 2, 눕기 2 |
| 가축 유년기 | 32×32 캔버스, 몸은 20×20 안쪽 | 같은 앵커(발 위치) |
| 건물 | 16px 격자 배수(48×48~96×96) | 위에서 비스듬히 본 시점(¾) |

- **팔레트**: 32색 고정. 털색 램프(각 4단계)를 인덱스 구간으로 예약한다. 공개 팔레트를 쓰면 라이선스를 확인한다.
- **광원**: 왼쪽 위. 외곽선은 램프의 가장 어두운 색(검정 금지).

### 4.3 맞춤 GPT 구성 (GPT를 쓸 경우)
- **켜는 기능**: 이미지 생성, 코드 인터프리터
- **지식 파일**: `style_guide.md`(위 규격), `palette.json`, 기준 스프라이트 PNG 5~10장, `postprocess.py`
- **지침(요지)**:
  1. 요청을 받으면 먼저 규격(크기, 단계, 방향, 프레임)을 확정한다.
  2. 기준 스프라이트를 참고해 큰 크기(예: 1024px)의 "픽셀 아트 스타일" 시안을 생성한다.
  3. 반드시 `postprocess.py`로 목표 크기에 맞추고 팔레트를 강제한다.
  4. 검증 보고(크기, 색 수, 팔레트 밖 색, 반투명 픽셀)를 붙여 PNG를 돌려준다.
  5. 같은 개체의 변이는 새로 생성하지 않고 팔레트만 교체한다.

### 4.4 후처리 파이프라인 (`tools/pixelize.py`)
```
입력 PNG → ① 픽셀 크기 추정(가장자리 간격의 최빈값) 
        → ② 셀마다 최빈색으로 다운샘플(평균 금지: 경계가 흐려짐)
        → ③ OKLab 거리로 고정 팔레트에 가장 가까운 색 매핑
        → ④ 알파 이진화(0 또는 255)
        → ⑤ 고립 픽셀 제거, 1px 외곽선 보정
        → ⑥ 목표 캔버스 중앙 정렬, 발 앵커 고정
        → ⑦ 검증: 크기 일치, 팔레트 외 색 0개, 반투명 0개, 색 수 ≤ 16
        → 출력 PNG + meta.json {size, anchor, paletteSlots, frames}
```
같은 스크립트를 이 오피스의 에이전트가 만들고 테스트할 수 있다. 이미지 생성만 GPT 같은 외부 도구에서 하면 된다.

### 4.5 런타임 팔레트 교체 (JS)
```js
// 기본 스프라이트는 털색 슬롯을 "마커 색"으로 칠해 둔다. 로드할 때 유전형 팔레트로 치환
function recolor(img, map){ // map: {'#ff00ff':'#3b2a20', ...}
  const c=new OffscreenCanvas(img.width,img.height), x=c.getContext('2d');
  x.drawImage(img,0,0); const d=x.getImageData(0,0,c.width,c.height);
  for(let i=0;i<d.data.length;i+=4){ const k=hex(d.data,i); if(map[k]) setHex(d.data,i,map[k]); }
  x.putImageData(d,0,0); return c;
}
```
`image-rendering: pixelated`과 정수 배율(×3, ×4)로 그려야 픽셀이 흐려지지 않는다.

### 4.6 작업 흐름
1. 기준 스프라이트 1세트를 사람이 Aseprite나 LibreSprite로 직접 다듬는다. 이것이 화풍의 기준이다.
2. 새 리소스: GPT로 시안 → `pixelize.py` → 사람이 5~10분 손질 → `assets/`에 커밋
3. 변이: 그리지 않고 `palettes/*.json`에 추가만 한다.
4. QA 에이전트가 검증 스크립트를 CI(커밋마다 자동 검사)처럼 돌려서 규격 위반을 잡는다.
